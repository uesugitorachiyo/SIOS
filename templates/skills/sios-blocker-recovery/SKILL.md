# Blocker recovery

Identify the required outcome, failed action, exact observed result, and independent work that remains. Inspect current evidence and applicable SIOS guidance; search relevant authorized Memory and read selected full sources and corrections. If the required Memory route is unavailable, report that gap and continue work that does not depend on it. Try available permitted alternatives without weakening access controls, repeating unsafe writes, or changing the user's scope.

Before declaring a blocker, state the exact remaining dependency, the observed failure, alternatives attempted, and the next executable action. A risk hypothesis or historical note alone is not a current denial. When an action later succeeds, distinguish the original failure, the verified change, and evidence connecting the two; leave the cause unknown when unproven. Only if the owner authorized capture and the client has the necessary scope, capture a minimal reusable result through the authorized Memory route with provenance and full readback. Otherwise report the result without storing it. Transient exploration does not require a record.
