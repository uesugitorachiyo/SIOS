# Local Factory

**Experimental feature branch:** This code is not production qualified. On the tested macOS and Windows hosts, the installed console command completed prepare, check, and an independently reviewed report at commit `7c3b0feff9aed6f81273fb026a411d4bac10b5ef`. The macOS run checked three tests; the Windows run checked eleven tests and four subtests. These are bounded trusted-code exercises, not exhaustive platform or security qualification. The macOS process monitor samples descendants and cannot exclude an unobserved escape.

Earlier attempts remain separate: a macOS test supervisor encountered `EPERM` before its Factory test started; a Windows review import failed with `PermissionError`, with its failing operation and cause unrecorded. An earlier workflow also used the changed checker to verify its own candidate, which does not independently establish that checker. The later successful runs do not establish the causes of those failures.

Factory prepares an isolated copy, checks the actual changed files, and records an independently supplied review. It does not run a model, fetch credentials, publish, or execute untrusted code safely. Candidate code runs with the local user's permissions.

Install the package with the `factory` extra on macOS; the extra supplies `psutil` for process observation. Windows uses the standard library and native Job Objects. Python 3.12 or newer is required by the package; the macOS process-custody gate currently admits only 64-bit CPython 3.12.13 with the expected Darwin signal ABI. Windows use requires a separately verified native environment and ordinary absolute executable paths. Local drive paths must satisfy the Windows path and link restrictions; long, network, device, reparse, or hard-linked paths are refused. Native qualification is specific to the tested host and interpreter.

For example, use the chosen Python explicitly: `PYTHON -m pip install '.[factory]'` on macOS or `PYTHON -m pip install .` on Windows. `PYTHON` denotes that interpreter's absolute path; a machine's default `python3` may be older and is not the release requirement. The package metadata fixes the build backend and the macOS Factory dependency. The core `tzdata` requirement is a range, so reproducible installation also requires an independently controlled dependency set and artifact hashes; this project does not claim a lockfile.

Use a fresh collection directory and serialize review imports. Historical claim-only partial review imports are not migrated or repaired. A check and a review import are consumed once; preserve incomplete or unknown evidence and do not retry it or switch sessions. A known-ended failed check or validated negative review can be named as a predecessor for a fresh run with fresh bounds.

Checks publish `SIMPLE_ACTIVE.json` in the collection before child launch, under the collection lock. An existing, partial, malformed or linked active or unknown marker holds prepare, check and report. It is removed only after a bound terminal record says the owned outcome is known ended. Preserve a held collection; do not delete markers, switch parent directories or retry the operation to bypass it. Recovery requires independently established termination and an explicit operator decision outside this tool. File data is flushed and synchronized, but filesystem failure or power loss can prevent durable directory metadata; the marker is not a guarantee against every storage failure.

On macOS, a checker killed or terminated abruptly can leave its child and descendants running and writing after the checker dies. The marker holds the collection; it does not stop or prove termination of those processes. Operator resolution must independently establish their end within the available observation limits before any new operation.

```
sios-factory prepare --request REQUEST.json --baseline-dir BASELINE --run-dir RUN [--bind-tools] [--predecessor PREVIOUS_RUN]
sios-factory check --run-dir RUN
sios-factory report --run-dir RUN [--review-receipt RECEIPT.json]
```

The request is a `factory-simple-request-v1` object with required fields `kind`, `allowed_paths`, `target_modules`, `test_modules`, `required_test_ids`, `criteria`, `implementer_id`, `implementation_session_id`, `python`, `git`, and `owner_hard_stop_utc`. Optional fields are `source_root`, `dependencies`, and `tracked_snapshot`. Each tool object contains an absolute `path` and `sha256`. With `--bind-tools` an omitted hash is filled from the selected ordinary file; a supplied mismatch is refused. The original request and binding are retained. Time is an explicit UTC timestamp ending in `Z`.

`source_root` is `.` by default or a relative candidate directory such as `src`. Product modules must originate there; test modules must originate under the candidate root. For a checkout, `tracked_snapshot` is `{"git_tree": "<40 lowercase hex>", "files": [...]}`. Each file row has exactly `path`, `mode` (`100644` or `100755`), `bytes`, and `sha256`, sorted by UTF-8 path. Windows tracked snapshots admit only `100644`; a `100755` row is explicitly refused. Supply the complete trusted inventory and expected Git tree from an independently verified commit. Root `.git` metadata is explicitly excluded and is never copied. Every other checkout entry must be accounted for; untracked files, extra directories, links and unsupported types are refused, not silently omitted. The reconstructed tree is checked against `git_tree`; the tool does not itself prove which commit supplied that tree. A copied baseline without `tracked_snapshot` still cannot contain `.git`.

Optional `dependencies` has exactly `root` (an absolute ordinary directory) and `files` (the same sorted file-row format). It is separate from the baseline and run. Its inventory is checked before and after tests, imported dependencies must match the supplied files, and the review packet contains the pinned dependency bytes. The original dependency directory and exact bytes must remain available and unchanged for report and predecessor operations too; a packet copy alone does not satisfy that requirement. Candidate files cannot shadow top-level module names derived from the dependency inventory. `.pth`, `.pyc`, links, reparse points, `.git` and `__pycache__` are refused; distribution metadata such as `.dist-info` is permitted. The limit is 10,000 files and 100 MiB, with the same 100 MiB cap on the entire review packet. The user supplies a trusted local dependency snapshot; no installation or ambient site-packages are used by the fixed `-S` bootstrap. The starting dependency and interpreter hashes bind selected local bytes, not independently verified publishers.

Dependency names are derived from files with suffixes recognized by the running interpreter, including importable files inside namespace-package directories. Data-only directories do not themselves cause a pre-import name refusal. If an imported namespace includes a dependency path, every location in that namespace must belong to the pinned dependency root; candidate/dependency namespace mixing is refused and accepted namespace paths are recorded.

The fixed bootstrap imports the requested candidate and test modules, checks origins and source immutability, and requires positive test counts, requested IDs, and no skipped or failing tests. A check has at most 120 seconds of productive time and 10 seconds for cleanup, further limited by the original owner stop. The review packet contains the request, baseline, candidate, full diff, process records, test results, and helper bytes. An external reviewer must supply a distinct reviewer session, exact run and packet identity, evidence, and the four verdicts `functionality`, `security`, `test_integrity`, and `verification_security`. The receipt records a local claim of independence; it is not cryptographic proof of reviewer identity.

The selected Python executable, loaded `subprocess`, base interpreter prefix and any virtual-environment configuration file are bound during preparation and checked again before and after the check. This detects drift after preparation, but the initial local interpreter and stdlib remain trusted inputs. Their hashes are not an independently established vendor signature. The macOS custody gate checks ordinary `Popen`, one main thread, default SIGCHLD and native signal disposition on each child entry. It cannot prove that unrelated native code will not reap a child; the caller must provide exclusive reaping custody. Mac termination records cover the direct child, sampled descendants and observed process groups; an escaped descendant missed between samples is not excluded. Unknown termination blocks further work.

On macOS, the `psutil` process observer is loaded from the caller's local environment. Its origin and hash are recorded, but are not pinned against an independent trusted value; its integrity is part of the trusted-local boundary.

On Windows, the bootstrap inventories extension files whose names appear in the trusted interpreter's `sys.stdlib_module_names` at its base `DLLs/<name>.pyd` paths before candidate imports. It requires the matching extension loader and regular, single-link, non-reparse files, and compares file paths and SHA-256 after testing. Other external origins remain unexpected; a flat Windows Python extension layout is not admitted by this exception. The base interpreter and dependent DLLs, including OpenSSL, remain trusted locally; hashes are drift checks, not publisher signatures or proof of mapped-image bytes. The selected `SystemRoot/System32` is the only inherited tool-search directory.

CLI output identifies confirmed facts, missing or unknown evidence, a next safe action, and evidence paths. A passing local test is not an independent review or a native qualification.
